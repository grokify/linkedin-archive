## [v0.1.0] - 2026-11-19 ([`f1d2e13`](https://github.com/grokify/linkedin-archive/commit/f1d2e13))

### Highlights

- Import LinkedIn data export archives (zip or extracted folder) into SQLite or PostgreSQL; repeat imports are safe and newer exports add only new records
- Full-text search over every message across Inbox, Archive and Spam, with phrases, `OR`, exclusion, prefixes and grouping on both databases

### Added

- `archive` package: open exports from a zip or folder, read CSV files by header name, skip preamble notes, strip byte-order marks, suffix repeated headers, and parse the export's date formats ([`02e73dd`](https://github.com/grokify/linkedin-archive/commit/02e73dd))
- Typed readers for messages (including `*_messages.csv` files), connections, invitations and saved items, with HTML-to-text conversion and stable content-hash keys for messages ([`02e73dd`](https://github.com/grokify/linkedin-archive/commit/02e73dd))
- Ent schema for import runs, people, connections, conversations, messages, invitations, saved items and raw records, with first-seen and last-seen import tracking ([`874d218`](https://github.com/grokify/linkedin-archive/commit/874d218))
- `store` package: open SQLite (`sqlite:<path>`, pure-Go driver) or PostgreSQL (`postgres://…`) by DSN and migrate the schema ([`7ec4cd8`](https://github.com/grokify/linkedin-archive/commit/7ec4cd8))
- `importer` package: idempotent import keyed by archive content hash; existing records are matched by natural key and only have their last-seen import and folder updated ([`d2f4201`](https://github.com/grokify/linkedin-archive/commit/d2f4201))
- Files without a typed table are preserved row by row in `raw_records`, so no export data is lost ([`d2f4201`](https://github.com/grokify/linkedin-archive/commit/d2f4201))
- Saved items from Complete exports, mapped by header name with unrecognized columns kept in `extra` ([`d2f4201`](https://github.com/grokify/linkedin-archive/commit/d2f4201))
- `search` packages: portable query syntax, SQLite FTS5 search with stemming kept in sync by triggers, and PostgreSQL full-text search with a GIN index and fully parameterized queries ([`f06c4ac`](https://github.com/grokify/linkedin-archive/commit/f06c4ac))
- `liarchive` CLI with `import`, `search` (`--from`, `--folder`, `--since`, `--until`, `--limit`, `--full`, `--json`), `imports`, `stats` and `saved` commands ([`6691ce9`](https://github.com/grokify/linkedin-archive/commit/6691ce9))

- GitHub Actions workflows for build and test, golangci-lint and CodeQL ([`b75401d`](https://github.com/grokify/linkedin-archive/commit/b75401d))

### Known Issues

- Saved-item column names have not yet been confirmed against a real Complete export; unrecognized columns are kept in `saved_items.extra`
- Posts, comments and reactions from Complete exports are stored only as raw records
- Timestamps without a time zone, such as invitation dates, are treated as UTC
