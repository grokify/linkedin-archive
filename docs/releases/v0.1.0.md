# Release Notes v0.1.0

**Release Date:** 2026-11-19

## Overview

This is the first release of `linkedin-archive`, a Go library and command-line
tool that turns LinkedIn data export archives into a searchable SQLite or
PostgreSQL database.

Import the `.zip` LinkedIn gives you, search every message in every folder,
and import newer exports as they arrive without creating duplicates.

## Installation

### CLI

```bash
go install github.com/grokify/linkedin-archive/cmd/liarchive@v0.1.0
```

### Library

```bash
go get github.com/grokify/linkedin-archive@v0.1.0
```

Requires Go 1.26 or later. No C compiler is needed.

## Highlights

### Import exports directly

- Reads the export `.zip` directly, or an extracted folder.
- Accepts both Basic and Complete exports and detects which one it is.
- Reads CSV files by header name rather than column position, so minor
  LinkedIn format changes don't break imports.
- Handles the export's quirks: the notes block at the top of
  `Connections.csv`, byte-order marks, repeated column names, HTML message
  bodies and many different date formats.

### Safe repeat imports

- The same export imported twice is detected by content hash and skipped.
- A newer export adds only new records. Existing records are matched, not
  duplicated.
- Each record stores the first and latest import it appeared in, so you can
  see what is new and what is gone between exports.
- Messages that moved folders between exports, for example Inbox to Archive,
  are updated in place.

### Full-text message search

- Searches subject, text and sender name across Inbox, Archive and Spam.
- Query syntax: words, `"phrases"`, `OR`, `-exclude`, `prefix*` and
  `(groups)`, the same on both databases.
- English stemming, so `shares` also matches `share`.
- Filters by sender, folder and date range, with text or JSON output.
- SQLite uses an FTS5 index kept up to date automatically. PostgreSQL uses
  built-in full-text search with a GIN index, with every search term passed
  as a query parameter.

### Nothing is lost

Messages, conversations, people, connections, invitations and saved items get
their own tables. Every other CSV file in the export is kept row by row in
`raw_records` as JSON.

### SQLite or PostgreSQL

- SQLite by default, using a pure-Go driver: one local file, no server.
- PostgreSQL through the same `--db` flag or the `LIARCHIVE_DB` environment
  variable.
- Tables are defined with Ent and created automatically.

## Commands

| Command | Description |
|---------|-------------|
| `liarchive import <zip or dir>...` | Import one or more exports |
| `liarchive search [query]` | Full-text search messages |
| `liarchive imports` | List imported exports |
| `liarchive stats` | Row counts per table |
| `liarchive saved` | List saved items |

## Go packages

| Package | Purpose |
|---------|---------|
| `archive` | Read exports and parse typed records |
| `store` | Open SQLite or PostgreSQL by DSN and migrate |
| `importer` | Repeat-safe import |
| `search`, `search/engine`, `search/sqlitefts`, `search/pgfts` | Message search |
| `ent` | Ent schema and generated client |

## Known limitations

- **Saved items** are mapped by header name. The column names have not yet
  been confirmed against a real Complete export; columns that aren't
  recognized are kept in `saved_items.extra`.
- **Posts, comments and reactions** from Complete exports are stored only as
  raw records for now.
- **PostgreSQL** is covered by an end-to-end test that runs only when
  `LIARCHIVE_TEST_POSTGRES_DSN` names a test database.
- **Times without a time zone**, such as invitation dates, are treated as
  UTC.
- **Connections from deactivated accounts**, which have only a date, are
  counted as skipped and not stored.
